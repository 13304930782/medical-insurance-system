# 医疗保险报销系统完整使用、配置与故障处理指南

## 系统定位、技术架构和数据原则

本系统是医疗保险中心业务管理与报销教学系统，使用 Maven、Java 17、Spring Boot、Spring Web、Spring Security、Thymeleaf、MyBatis 和 MySQL。IDEA 用于打开含 pom.xml 的 medical-insurance-system 目录、同步 Maven 和运行 MedicalInsuranceApplication；Navicat 用于查看 MySQL 数据。浏览器默认访问 http://127.0.0.1:8080。后端按 controller、service/impl、dao、model、exception、config 和 util 分层；MyBatis XML 位于 resources/mapper。前端入口是 templates/index.html，登录、菜单和 AI 助手拆到 templates/fragments，样式与交互分别位于 static/css 和 static/js。

《数据库一览表》规定的原始表名、字段名和原拼写不修改。新账号安全、日志、批量任务、AI 知识库、结算明细等功能放在 ext_ 扩展表。不要为了界面方便重命名原表字段，也不要直接删除有业务引用的账务数据。

## 登录、邮箱登录、注册和会话

登录框支持“用户名或注册邮箱 + 密码”。邮箱匹配不区分大小写。登录密码通过浏览器 RSA-OAEP 加密后发送，数据库只保存 BCrypt 哈希。连续登录失败达到限制时账号会临时锁定 15 分钟。登录成功后建立服务器会话；账号被删除、密码被修改或会话版本变化时，旧会话会失效并要求重新登录。

注册页填写登录账号、真实姓名、唯一邮箱、密码和确认密码。账号只能使用字母、数字、下划线且为 4 至 30 位；密码为 8 至 64 位可见英文字符，必须同时包含大写字母、小写字母、数字和特殊字符。新注册账号状态为“待审核”，管理员进入“账号审核与操作日志”后选择通过为审批员或通过为经办员；未审核账号不能登录。

忘记密码必须填写账号和注册邮箱。系统向邮箱发送六位验证码，验证码 10 分钟有效，连续错误 5 次失效，同一账号 60 秒内只发送一封。收到验证码后在同一页填写验证码、新密码和确认密码。发送较慢时等待按钮结束加载，不要重复点击；未收到时检查 SMTP 环境变量、发件箱、垃圾邮件和应用日志。右上角“修改密码”要求当前密码和新密码，成功后当前会话退出。

## 角色、菜单和权限

ADMIN 是系统管理员：可以使用 Dashboard、全部基础资料、待遇参数、待遇审批、报销结算、批量数据、账号管理、日志和 AI 官方资料同步。APPROVER 是待遇审批员：主要显示人员就诊机构审批和特检特治审批。REIMBURSEMENT 是报销经办员：主要显示 Dashboard、中心报销、综合查询、正式结算和取消报销。菜单按角色隐藏，直接请求无权限接口会返回 403，AI 只能解释操作，不能绕过权限。

管理员在“账号审核与操作日志”的账号列表中审核注册申请。普通账号可以“删除账号”：这是可恢复删除，账号立即不能登录、旧会话失效，但历史业务和日志保留。筛选“已删除”后可以恢复，恢复到删除前状态；管理员不能删除自己或其他 ADMIN 账号。

## Dashboard 首页和完整个人报销流程

进入“报销办理 Dashboard”，首页指标显示参保人员、参保单位、待结算就诊、本年正式结算和本年基金支付。饼图显示每种参保单位类型的数量和百分比。年份框改变年度统计，“刷新”重新读取指标。

个人报销流程：第一步选择“个人报销”，输入个人编号、姓名、证件号或社保卡号，点击“查询办理对象”并选中人员；第二步点击就诊登记，选择医疗类别、定点机构、医院等级、病种、入院日期等并保存；第三步选中就诊，新增一条或多条处方；第四步点击预结算，核对费用构成和每项计算说明；第五步确认正式结算；第六步在清单中打印，或到“综合查询与取消”再次查看。

单位报销流程：切换“单位报销”，先搜索并选中参保单位，再从该单位人员中选择办理对象，后续就诊、处方、预结算和正式结算步骤与个人报销相同。切换单位会清除上一个单位的人员选择，防止把人员记到错误单位。

## 门诊号、住院号和就诊资料

新增门诊就诊时不要求用户手工编门诊号。选择人员后，系统检查该人员是否存在可沿用的未结算门诊记录；存在时弹窗询问是否沿用。选择沿用会打开原记录继续录处方；选择不沿用或没有历史记录时，后端按业务序列自动生成递增门诊号。住院业务可以按实际资料填写住院号。

就诊资料必填个人编号、医疗类别、定点医疗机构、医院等级、病种和入院日期。出院日期不能早于入院日期。人员、病种和机构必须在基础资料中存在。已正式结算的就诊不能再随意修改或删除；未结算就诊可以继续编辑处方。

如果查询不到人员，先到“个人信息维护”确认个人存在、所属单位正确，再清空查询条件重新搜索。如果机构或病种下拉为空，先检查对应基础资料是否有效。医院等级应与定点机构资料一致。

## 处方目录联动、项目编码和收费类别

新增处方先选择“从目录选择”或“手工录入”。目录类别有药品、诊疗项目、服务设施；选择目录类别后，收费项目类别和项目编码候选必须联动过滤。药品只能出现西药、中成药、中草药等药品收费类别；诊疗项目只出现诊疗收费类别；服务设施只出现床位费等服务设施类别，不能选择西药或中成药。

项目编码候选显示编码、名称、甲乙丙类别、报销比例和是否需要审批。先选收费项目类别时，编码候选只显示该类别项目；先选项目编码时，系统自动回填与该项目一致的目录类别、收费类别、名称和单价。项目编码输入框右侧“×”用于一键清空错误选择。特检特治审批的项目列表只显示所选项目类别中确实需要审批的药品或诊疗项目。

手工录入项目可以不填编码，系统自动生成手工项目编号，但该项目按全额自费处理。数量必须大于 0，单价不能小于 0。总金额由后端按单价乘数量重新计算，不以浏览器传来的总额为准。

## 目录有效期、甲乙丙类别和计算说明

药品、诊疗项目和服务设施都有有效标志、开始时间和结束时间。结算日期不在有效期内、有效标志不是有效、目录不存在时，项目显示“目录项目无效或不在有效期，全额自费”。修改目录有效期可以在相应维护页面编辑，批量修改则使用“批量数据管理”导入更新后的 XLSX；更新后要重新预结算。

目录类别报销规则由实际表字段和参数决定。甲类通常全额进入医保计算范围，乙类先扣项目类别自费，丙类或手工项目通常全额自费；最高限价以上部分自费。页面“项目计算明细”展示总费用、纳入医保、项目自费和具体计算说明。程序以数据库当前字段和维护参数计算，不硬编码演示金额。

## 药品、诊疗、设施、病种和定点机构维护

ADMIN 在“医疗基础信息”下维护药品、诊疗项目、服务设施、病种和定点医疗机构。每个页面顶部可按编码或名称查询，“重置”清空条件；“新增”打开表单，表格行内“编辑”读取原记录，“删除”需确认。主键重复、必填字段为空或仍被其他业务引用时，后端会给出错误，不能靠前端绕过。

药品维护包含药品编码、名称、收费类别、报销等级、最高限价、开始/结束时间、有效标志、医院等级和审批要求等。诊疗项目字段结构相近。服务设施使用服务设施原表字段，收费类别必须属于设施类。病种维护病种编码和名称等原字段。定点机构维护机构编码、名称、医院等级、有效信息等；审批和就诊所选机构必须存在。

## 参保单位和个人信息维护

“单位信息维护”支持按单位编号或名称查询、新增、编辑和删除，单位类型来自数据字典。Dashboard 饼图按单位类型统计，因此单位类型为空或写法不一致会影响分类结果。

“个人信息维护”支持个人编号、姓名、证件号、社保卡号等查询。个人必须关联存在的参保单位，证件类型、性别、民族、国籍、身份、用工形式等从参数数据字典选择。测试身份证号必须使用虚假数据，不要录入真实敏感身份信息。存在就诊或结算引用的个人不能直接删除。

## 医疗待遇计算参数

ADMIN 进入“医疗待遇计算参数”，通过三个页签维护基金封顶线、起付标准和个人分段自费比例。封顶线按医疗人员类别维护；起付标准按医疗类别、人员类别和医院等级组合维护；分段比例还包含下限金额和上限金额。

金额必须大于等于 0；分段下限必须小于上限；同一医疗类别、人员类别和医院等级下区间不能重叠。报销比例页面按 0 至 100 的百分数输入，数据库按 0 至 1 保存。预结算提示找不到起付标准、分段比例或封顶线时，先检查就诊的医疗类别、个人类别和医院等级是否与参数文字完全一致。

## 人员就诊机构审批

APPROVER 或 ADMIN 进入“人员就诊机构审批”，可查询、新增、编辑和删除审批。新增需要审批编号、个人编号、定点医疗机构编码、审批标志，并可填写开始日期、终止日期、意见、审批人和审批时间。审批人为空时默认当前登录人员。

报销计算只采用人员、机构匹配，审批通过且结算日期在有效期内的记录。审批过期、未通过、人员不匹配或机构不匹配时，不能作为有效审批。日期为空时按系统允许的开放边界处理，若需要严格期限应同时填写开始和终止日期。

## 特检特治审批

APPROVER 或 ADMIN 进入“特检特治审批”。先选药品或诊疗项目，再选择项目编码；候选只显示相应目录中标记为需要审批的项目，不应显示无需审批项目或其他类别项目。填写审批编号、个人编号、项目、有效期、审批标志、意见、审批人和审批日期后保存。

结算时必须同时匹配人员、项目编码、审批通过状态和有效期。原药品审批继续使用原表 drug_Code 字段，诊疗项目审批信息放在扩展数据中，不修改原表字段。

## 预结算、正式结算和费用顺序

选中未结算就诊并录完处方后点击“预结算”。预结算只计算和展示，不创建正式结算、不更新个人年度累计，可以在修正目录、审批、参数或处方后重复执行。

计算顺序是：校验人员、病种和定点机构；校验机构审批与特检特治审批；逐条处理目录有效期、最高限价、甲乙丙类别、医院等级和项目审批；汇总纳入基本医保费用；扣起付标准；按实际分段上下限计算个人分段自付；应用年度累计和封顶线；最后生成基金支付和个人费用构成。

确认正式结算后，系统在一个数据库事务内写结算主记录、逐项计算明细、费用构成、个人年度累计、就诊结算标志和操作日志。相同就诊不能重复正式结算。确认前必须核对人员、项目和金额；正式结算后应通过取消流程冲正，不能直接改数据库。

## 综合查询、打印和取消报销

进入“综合查询与取消”，可按个人编号、姓名、住院号或门诊号、结算编号和年度查询。点击查看打开结算清单，包含人员与就诊概要、总费用、医保纳入、项目自费、起付线、分段自付、基金支付、个人费用和项目计算明细。“打印清单”调用浏览器打印，只打印结算区域。

取消报销只允许已正式结算且尚未取消的记录。点击“取消报销”并填写取消原因，系统保留原正交易，新增关联负交易，在同一事务中恢复年度累计并记录操作日志。重复取消会被拒绝。取消不是删除原结算记录。

## 批量模板、XLS/XLSX 导入、导出和安全删除

ADMIN 进入“批量数据管理”，先选择数据模块。推荐点击“下载空白模板”，按模板列名填写后上传 XLS 或 XLSX；药品、诊疗项目和服务设施也兼容原《数据.xls》的对应页签。JSON 不是当前批量页面的标准导入格式。

导入模式包括“仅校验，不写入”“新增或更新”“仅新增，重复报错”。第一次导入建议先仅校验，根据错误行修正文件，再选择新增或更新。导出当前数据会生成 XLSX。批量任务记录总数、成功数、失败数和错误原因。

安全批量删除要求每行填写一条精确主键；复合主键按页面说明使用英文竖线分隔，并输入指定的 DELETE N 确认文字。存在外键引用时数据库会拒绝。结算、年度累计等账务数据不开放通用批量删除。

## 操作日志查询和导出

ADMIN 在“账号审核与操作日志”查看“业务操作日志”。日志记录谁在什么时间对哪个业务对象执行了什么动作、详情、结果和 IP。登录、退出、注册、找回密码、增删改、审核、导入导出、正式结算、取消和账号删除恢复会留痕；普通页面加载和只读 GET 查询不作为业务操作展示，避免日志被无意义请求淹没。

查询框支持操作人、模块、动作、业务编号和详情，结果可以筛选成功或失败。“导出 XLSX”导出当前业务日志。历史日志用于审计，不应因为账号软删除而消失。

## AI 问答使用和知识来源

登录后点击右下角黑色聊天图标。用户消息显示右侧，助手显示左侧。系统操作问题始终读取本内置指南，不需要也不会触发国家医保局联网搜索；回答应给出当前角色可用的菜单路径、步骤、字段联动和故障检查。医保政策问题使用已同步的国家医疗保障局资料，证据不足时才按问题到官网增量检索。

回答正文中的“[资料N]”和回答下方的完整资料名称都可以点击。点击后进入“系统帮助中心”，打开对应资料并自动定位、高亮到引用段落；“返回刚才页面”会回到进入帮助前的业务页面和原滚动位置。左侧菜单也有“系统帮助中心”，可以直接阅读完整指南。官方政策资料的帮助页提供“打开官方原文”。

DeepSeek 通过 AI_ENABLED=true、DEEPSEEK_API_KEY 和可选的 DEEPSEEK_BASE_URL、DEEPSEEK_MODEL 配置。ADMIN 可在聊天窗口查看官方资料数量并点击“立即同步”。内置系统指南是系统问答的必要资料，页面不允许删除。AI 不读取业务密码、数据库口令或 API Key，不替用户执行增删改、审批、结算和取消。

## SMTP 邮件配置和排查

邮件环境变量通常包括 SMTP_HOST、SMTP_PORT、SMTP_USERNAME、SMTP_PASSWORD、SMTP_AUTH 和 SMTP_STARTTLS。密码通常是邮件服务商提供的 SMTP 授权码，不一定是邮箱网页登录密码。RESET_MAIL_ENABLED=true 后忘记密码才实际发信，RESET_MAIL_FROM 应与服务商允许的发件地址一致。修改环境变量后必须停止并重新启动应用。

邮件发送慢通常发生在 DNS、连接 SMTP、TLS 握手或服务商投递阶段。界面发送按钮在请求期间显示加载并禁止重复点击；后端提交后异步发送，60 秒内重复申请不会创建多封新邮件。应用日志出现认证失败时检查账号和授权码，连接超时时检查主机、端口、防火墙、TLS 与网络。

## IDEA、Maven、MySQL、端口和 HTTPS

IDEA 必须打开 medical-insurance-system 文件夹而不是更外层资料目录。右侧 Maven 面板能看到项目、生命周期、插件、依赖项和仓库即表示已识别；常用验证为 Maven test 或 package。运行配置选择 MedicalInsuranceApplication，并在环境变量中配置 DB_USERNAME、DB_PASSWORD、DeepSeek 和 SMTP。修改源码后重新运行，修改环境变量必须完全停止旧进程再启动。

启动报“Port 8080 was already in use”表示已有一个程序占用 8080，通常是旧的 Spring Boot 进程仍在运行；停止旧运行实例后再启动，不要同时运行两个项目。页面能打开但新功能不出现时先重启后端，再用 Ctrl+F5 强制刷新浏览器静态缓存。接口大量返回 401 表示未登录、会话失效或前端仍使用旧会话，应重新登录；403 表示当前角色无权限。

数据库默认连接 medical_insurance_reimbursement。启动时 Flyway 自动检查和应用 ext_ 扩展迁移。不要重复手工运行已经由 Flyway 执行的迁移。MySQL 连接失败时检查服务是否启动、库名、端口 3306、账号密码和 IDEA 环境变量。

localhost 可以使用 HTTPS，但需要本地证书和 server.ssl 配置，浏览器可能提示不信任自签名证书。只在本机演示时 HTTP 可工作；需要跨网络部署、真实账号或公网访问时应使用受信任证书、HTTPS、反向代理和安全的环境变量管理。

## 常见业务故障定位

登录后页面一闪又回登录页：先看浏览器网络请求，/api/auth/login 成功但 /api/auth/me 为 401 通常是会话或旧后端问题；确认只运行一个 8080 实例，重启后 Ctrl+F5。登录框支持用户名或邮箱，邮箱必须是注册时唯一邮箱。

项目显示全额自费：查看项目计算说明。常见原因是目录无效或过期、手工项目、丙类、超过最高限价、缺少有效特检审批、收费类别与目录不匹配。修改后重新预结算。

报销或预结算提示“人员未进行特检审批”：这属于本系统业务校验，不需要补充参保地区。先确认处方选择的是目录中标记为“需要审批”的项目；再由 APPROVER 或 ADMIN 进入“特检特治审批”，选择同一个人员、同一种项目类别和完全相同的项目编码，将审批状态设为通过，并确保审批有效期覆盖本次就诊或结算日期。人员、项目编码、审批状态、开始日期和终止日期任一不匹配，系统都会认为没有有效审批。保存后回到报销页面重新预结算；如果项目本来不应审批，则到药品或诊疗项目维护中核对该目录项目的审批要求，不要为错误标记的项目补造审批。

预结算找不到待遇参数：核对就诊医疗类别、个人医疗人员类别、医院等级与起付标准、分段比例、封顶线的组合和值是否一致，检查区间是否覆盖当前金额。

项目编码下拉出现错误类别：先清空项目编码，再选目录类别和收费项目类别；系统应只返回对应候选。服务设施不允许西药、中成药或中草药，特检审批不允许选择无需审批项目。

查询一执行就报错：记录页面、查询条件、HTTP 状态和后端第一段异常。401 先重新登录，403 检查角色，400 查看业务提示，500 查看 IDEA 控制台最早的 Caused by。不要只截最后一行堆栈。

## 系统助手回答边界

系统助手可以解释本项目所有已实现页面、菜单、按钮、字段、角色、业务流程、计算顺序、配置、数据导入、操作日志和常见报错。回答时应引用“医疗保险报销系统完整使用、配置与故障处理指南”，并以当前代码已实现功能为准。若问题涉及某条真实业务数据、密码、密钥或要求 AI 代替用户执行写操作，助手应说明不能读取敏感信息或不能代执行，再给出用户可以在页面完成的步骤。

系统助手不能把本系统演示规则冒充全国统一医保政策。用户明确询问国家、地方、异地就医或最新政策时，应切换到国家医保局官方资料；没有地区或证据时要求补充参保地，并明确资料不足，不能猜测。
